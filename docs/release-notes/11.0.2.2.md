## What's changed

A dependency refresh, and the first release where the Android initialization is actually
initialization.

### Fixed

- **Android initialization did nothing.** `InitializeAsync` configured MobilePush through
  `MarketingCloudSdk.init`, the pre-Unified-SDK entry point, which at v11 hands the engagement
  module a null `SFMCSdkComponents` and dies inside `getEncryptionManager` — while still calling its
  listener back, so the façade reported success over an SDK that never came up and `requestSdk`
  never fired. Configuration now goes through `SFMCSdk.Configure` with `MarketingCloudConfig`
  attached as the engagement module config, which is what the sibling
  `MarketingCloudSDK.Net.Android` repository's own sample and device tests do (see its `11.0.1.2`
  notes). iOS was never affected — it already initialized through the core.
- **`EditAsync` could hang forever on Android.** The `requestSdk` queue it waits on never drains if
  the SDK is not coming up, and the wait was unbounded. It is now bounded by the same timeout
  initialization uses (`MarketingCloudOptions.InitializationTimeout`, or its 30-second default for
  an edit issued before initialization) and expiry surfaces as `TimeoutException`.
- **The iOS timeout fallback now documents what it actually proves.** Measured against 11.0.2 in a
  simulator: the core's module roster reports `pushfeature` whether or not a push config was ever
  supplied, and in an unprovisioned tenant every module reads `"status": "inactive"`. The fallback
  is deliberately kept — failing there would refuse to initialize on exactly the unprovisioned
  tenants it exists for — but the code and docs no longer imply it verifies the module concluded.

### Added

- **`TrackCustomEvent`** on `IMarketingCloudClient`, forwarding to the SFMC SDK core the façade
  already composes. Custom events moved to the core at v11 exactly as identity did; previously the
  README sent you to the raw platform namespaces for them, which was worse advice than the
  cross-platform API sitting in an already-referenced package.
- **`IsSupported` and `IsInitialized`** on `IMarketingCloudClient` — the two members that answer on
  every target framework instead of throwing, so shared code has something to branch on. Neither is
  the one-shot guard: after a failed initialization `IsInitialized` stays false while the guard
  stays claimed.
- **`NullMarketingCloudClient`** — the no-op implementation the README used to tell consumers to
  write themselves, for MAUI heads with no SDK and for tests. It validates its arguments, so it
  hides platforms without hiding caller bugs.
- **`UseMarketingCloud()` / `AddMarketingCloud()` without options**, for apps whose credentials are
  not known at composition time (a signed-in user's tenant, a runtime prompt). Previously those apps
  got nothing from the `.Maui` package and hand-wrote the `AddSingleton` themselves — as this
  repository's own sample did, which is why the package's headline API was never exercised in CI.
- **`build/RepinPackages.sh`** — the re-pin helper the upstream-drift issue template has been
  pointing at under a name that did not exist. It rewrites the props and reports what the README
  still owes, leaving `CheckReadmeVersions.sh` as the gate.
- **A cross-repo pin agreement package test.** The MobilePush bindings and the core umbrella must
  agree on the `SFMCSDK.Net.Android`/`.iOS` revision underneath them; that was documented in a
  csproj comment and asserted nowhere, which is how the two lines drifted apart once already.

### Dependencies

- Re-pinned to the newest downloadable NuGet builds:
  [`MarketingCloudSDK.Net.Android 11.0.1.2`](https://github.com/sbokatuk/MarketingCloudSDK.Net.Android/releases/tag/v11.0.1.2),
  [`MarketingCloudSDK.Net.iOS 11.0.2.2`](https://github.com/sbokatuk/MarketingCloudSDK.Net.iOS/releases/tag/v11.0.2.2)

  all pinned exactly in `Directory.Build.props`.
- Bumped this repository's release revision from `11.0.2.1` to `11.0.2.2` to reflect the new pin
  set.

### Upgrading

Source-compatible for consumers. Implementers of `IMarketingCloudClient` — a hand-written test fake
— must add `TrackCustomEvent`, `IsSupported` and `IsInitialized`, or switch to
`NullMarketingCloudClient`. MAUI Android apps on the net10 head need a direct
`Xamarin.AndroidX.Lifecycle.LiveData.Core 2.10.0` reference to settle the graph against MAUI
10.0.20; see the README's troubleshooting section.
