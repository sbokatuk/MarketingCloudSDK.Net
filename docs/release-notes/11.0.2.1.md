## What's changed

First release of the cross-platform façade over the Marketing Cloud MobilePush bindings.

- **One API on both platforms**: `MarketingCloudClient` with awaitable `InitializeAsync` (real
  credentials, feature toggles, timeout, log level), `Identity` (contact key and attributes via
  the SFMC SDK core), `Registration` (contact key / device id / push token reads, tag and
  attribute edits) and `DiagnosticState`, over
  [`MarketingCloudSDK.Net.Android 11.0.1.1`](https://github.com/sbokatuk/MarketingCloudSDK.Net.Android/releases/tag/v11.0.1.1),
  [`MarketingCloudSDK.Net.iOS 11.0.2.1`](https://github.com/sbokatuk/MarketingCloudSDK.Net.iOS/releases/tag/v11.0.2.1)
  and [`SFMCSDK.Net 4.0.1.1`](https://github.com/sbokatuk/SFMCSDK.Net/releases/tag/v4.0.1.1),
  pinned exactly. The version names the iOS line (MarketingCloudSDK 11.0.2); the Android side is
  marketingcloudsdk 11.0.1.
- **The platform asymmetries are absorbed, not papered over**: Android's `init` listener becomes
  an await with an options-driven timeout linked to the caller's `CancellationToken`; on iOS the
  same await knows that the completion block reports *concluded* module statuses and so may
  never fire against an unprovisioned tenant - measured upstream behaviour, encoded in the
  binding repository's device tests - and falls back to the SDK's state JSON reporting the push
  module. `editor.SetAttribute` maps to `sfmc_setAttributeNamed:value:` on iOS and to the core
  identity write on Android, where the v11 editor dropped its attribute members; nothing
  silently no-ops anywhere.
- **Identity is composed, not reimplemented**: v11 moved contact key and attributes to the SFMC
  SDK core, so `Identity` hands out SFMCSDK.Net's `ISfmcIdentity` - and on iOS `SetProfileId`
  also pushes the module's `sfmc_setContactKey:` shim so both identity planes agree.
- **`MarketingCloudSDK.Net.Maui`**: `UseMarketingCloud` / `AddMarketingCloud` register
  `IMarketingCloudClient` as the documented singleton alongside the options. Thin by design -
  v11 observes the push token itself on both platforms, so there is no lifecycle wiring for a
  MAUI package to hide. iOS assets for net8/net9/net10; Android for net10 only, because MAUI
  8/9's AndroidX generation is irreconcilable with MobilePush 11's (the csproj documents the
  measured conflict).
- **Nine target frameworks for the façade** - `net8.0`, `net9.0`, `net10.0`, each with
  `-android` and `-ios` heads. The plain assets restore anywhere, carry the composed
  `ISfmcIdentity` surface, and throw `PlatformNotSupportedException` naming the platform heads
  from every native-backed member, so shared class libraries, unit tests and a MAUI app's
  Windows head reference the package with no conditionals.
- **Nothing is hidden**: the raw namespaces `Com.Salesforce.Marketingcloud`,
  `MarketingCloudSDK` and `SFMCSDK` arrive with the package on their platform - inbox models,
  in-app messages, location messaging and the rest stay one `using` away.
- Licence is plain `MIT` on both packages: they ship no native binaries; Salesforce's
  BSD-3-Clause arrives with the binding packages, each of which declares and packs both texts.
